| F02 · Controlled recording | Opt-in test-API middleware records projected requests and response snapshots, with replayable aliases | Recording round trip and response-evidence test |

| F11 · CI replay | Unit/integration tests, clean replay, Docker/Playwright tests, PR annotations, reusable Action and artifact upload | See Replay verification on GitHub Actions |

## Test matrix

The tests cover different generated IDs, timestamp-only changes, missing currency, stale discount, HTTP 500, duplicate notification effects, sensitive headers, forward references, unknown fixtures, attempted external delivery, object-key reordering, array reordering, absent fixture leases/reset failures, and bounded timeouts. Additional tests exercise finite polling, immutable writes, Git provenance, trace export, S3 contents, retention, worker lease theft/recovery, and the live browser workflow.

## Later milestones

- PostgreSQL persists scenarios, steps, runs, per-environment evidence, grouped differences and a checksummed artifact index.
- The React history dashboard includes run inspection, first divergence, grouped regressions, daily trends and compared route/field coverage.
- Process-isolated workers claim bounded jobs and prioritize scenarios using prior failures. S3-compatible storage retains immutable payloads through an upload outbox.
- GitHub Actions emits scenario-file annotations and includes a reusable composite Action. The PR gate compares the base and head source commits.
- OpenTelemetry exports target and HTTP-step spans. Scenario GET steps can poll within explicit bounds.
- The published benchmark, actual Git comparison, browser snapshot and terminal recording are generated by repository tools. The reproducibility check compares six clean runs with their committed step evidence.
